# 🤖 AI Knowledge Agent

An AI-powered knowledge assistant that answers user questions using a custom dataset, semantic search, and a large language model (LLM). The project combines data cleaning, vector embeddings, retrieval-augmented generation (RAG), and a FastAPI backend to generate context-aware responses grounded in retrieved information.

The goal is to build a reliable, extensible AI agent with a continuously maintainable knowledge base and a path toward production deployment.

## ✨ Features

- **Data preprocessing:** Cleans records, handles missing values, removes duplicates, and validates required fields.
- **Semantic search:** Uses Sentence Transformers to convert documents and queries into vector embeddings.
- **Vector similarity search:** Uses FAISS to retrieve relevant knowledge efficiently.
- **LLM-powered responses:** Uses Google Gemini to generate answers based on retrieved context.
- **Source-aware responses:** Returns metadata about the documents used to support an answer.
- **Basic relevance filtering:** Avoids answering when the best retrieval score falls below a configurable threshold.
- **Evaluation pipeline:** Tests whether expected documents are retrieved for predefined questions.
- **REST API:** Exposes the agent through FastAPI.
- **Interactive API documentation:** Supports endpoint testing through Swagger UI.
- **Modular architecture:** Separates data cleaning, retrieval, response generation, evaluation, and API handling.

## ⚙️ Installation and Setup

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd ai-agent-project
```

### 2. Create a virtual environment

Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If activation is blocked, use Command Prompt:

```bat
.venv\Scripts\activate.bat
```

### 3. Install dependencies

Create `requirements.txt`:

```text
pandas
numpy
sentence-transformers
faiss-cpu
python-dotenv
langchain-google-genai
fastapi
uvicorn
```

Install the packages:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

For reproducible deployments, pin and test compatible dependency versions after establishing a working environment.

### 4. Configure the API key

Create a `.env` file in the project root:

```dotenv
GOOGLE_API_KEY=your_actual_google_api_key
```

Obtain an API key through [Google AI Studio](https://aistudio.google.com/).

Never commit API keys, passwords, or other secrets to GitHub.

### 5. Prepare the dataset

Place the raw dataset at:

```text
data/documents.csv
```

The initial implementation expects these columns:

| Column | Description |
|---|---|
| `id` | Unique document identifier |
| `title` | Document title |
| `content` | Knowledge content |
| `source` | Source identifier |
| `updated_at` | Update date |

The included example dataset is intended for development and testing. Replace it with appropriate, verified data for your intended application.

## 🚀 Running the Project

### Step 1: Clean the dataset

```bash
python data_pipeline.py
```

This generates `data/cleaned_documents.csv`.

### Step 2: Run the AI agent

```bash
python agent.py
```

Example interaction:

```text
AI Knowledge Agent is ready.
Type 'exit' to stop.

You: What does HTTP 401 generally indicate?

Agent:
HTTP 401 generally indicates missing or invalid
authentication credentials.

Retrieved sources:
- HTTP status codes (similarity: ...)
```

Actual responses and similarity scores depend on the model, data, and environment.

### Step 3: Run the evaluation

```bash
python evaluation.py
```

The evaluation script checks whether expected sources appear in retrieved results for predefined questions. It does not independently establish factual answer accuracy.

### Step 4: Start the REST API

```bash
uvicorn app:app --reload
```

Once running, access:

- Health check: `http://127.0.0.1:8000/health`
- Interactive API documentation: `http://127.0.0.1:8000/docs`

Example request:

```json
{
  "question": "How can I troubleshoot a Python API connection error?"
}
```

Send the JSON body to `POST /ask` through Swagger UI or an HTTP client.

## 🔍 How It Works

### 1. Data preparation

The pipeline reads the source CSV, normalizes fields, removes incomplete records and duplicates, validates dates, and saves the cleaned dataset.

### 2. Embedding generation

The Sentence Transformers model `all-MiniLM-L6-v2` converts document text into vector representations.

### 3. Retrieval

FAISS uses inner-product similarity over normalized embeddings to retrieve candidate documents relevant to a question.

### 4. Response generation

Retrieved content is passed to Google Gemini with instructions to use the supplied evidence, acknowledge uncertainty, and cite retrieved source labels.

### 5. Basic evaluation

A predefined set of questions is used to check retrieval behavior and identify potential failures.

## 🔄 Updating the Knowledge Base

To add or modify information in the current version:

1. Update `data/documents.csv`.
2. Run `python data_pipeline.py`.
3. Restart `python agent.py` or restart the API process so the updated dataset and index are loaded.

The current implementation rebuilds the index at startup. It does not yet automatically monitor external sources or incrementally update individual documents.

## 📊 Evaluation and Reliability

Retrieval relevance is not the same as answer correctness. The current evaluation provides a basic retrieval match rate.

Future evaluation should measure:

- Retrieval Recall@k.
- Answer correctness against reviewed reference answers.
- Evidence faithfulness and citation correctness.
- Performance on irrelevant and ambiguous questions.
- Appropriate abstention when evidence is insufficient.
- Response latency, API failures, and operational cost.

The current similarity threshold is a heuristic and should be calibrated using representative evaluation data. A high similarity score does not guarantee a correct answer.

## 🔐 Security and Limitations

- Keep credentials in environment variables or a suitable secrets manager.
- Do not upload sensitive data without reviewing privacy and provider data-handling requirements.
- Validate and restrict access to tools before allowing the agent to perform actions.
- Treat retrieved documents and user content as untrusted input.
- Add authentication, rate limiting, monitoring, and access controls before public deployment.
- Review data licenses and applicable privacy requirements before collecting or processing external data.

This project currently uses a pretrained LLM; it does not train a foundation model from scratch. It also does not yet implement automated source ingestion, persistent vector-index management, fine-tuning, or production-scale monitoring.
